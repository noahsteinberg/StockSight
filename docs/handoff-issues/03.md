# Hosted market data: decide coverage and implement validated incremental daily refresh

Priority: required before claiming current multi-stock coverage.

Current state: production Supabase contains the 506-bar AAPL historical sample ending 2017-02-16; the larger 494-stock snapshot through 2026-11-12 is local. Production is not a live market feed.

Scope:
- Review provider terms/coverage and raw versus adjusted OHLC/close conventions using existing Yahoo feasibility docs.
- Decide first hosted universe (AAPL first is acceptable), snapshot import versus recurring refresh, storage budget and explicit freshness policy.
- Backend-owned provider adapter; normalize symbols, exchange sessions, source/fetch timestamps, settled/provisional status, missing/bad bars and bounded retries.
- Scheduled ingestion separate from HTTP chart requests; idempotent upsert and sanitized job status. Do not choose a paid service silently.
- UI retains actual source/as_of/coverage labels; distinguish quote refresh from daily ML cadence.

Acceptance:
- Recorded-provider-fixture tests, holidays/weekends, duplicates, failures/stale data and adjustment handling.
- No silent provider fallback, browser secrets, full-universe downloads per request or automatic replacement of hosted data.
- Publish real coverage/freshness evidence before changing UI claims.
